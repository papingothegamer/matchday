🔒 Role-Based Authorization

Access control is securely handled via Django views using `@login_required` and `is_staff` restrictions:

  • Super Admin: Standard Django administration panel at `/admin/`.
  • League Admin (staff): Creates tournaments, generates fixtures, enters match results, and auto-simulates.
  • Coach (regular): Registers their team/players, views opponents' squads, stats, and live standings.

🔄 CRUD Life Cycle

Demonstrates full relational data CRUD operations across different user roles:

  • Create: Coach registers a team & players; League Admin creates a tournament.
  • Read: Browse tournaments, view computed standings, top scorers, and team lineups.
  • Update: Admin enters exact match scores/player stats or edits tournament details.
  • Delete: League Admin can delete a tournament.

⚡ Standings Aggregation & Optimization

Optimization Pattern: Recalculating league standings on every read page load is computationally heavy. Instead, the application uses a denormalized pre-computed `Standing` table.

Whenever an admin enters/updates a match result, the backend recalculates and saves rows to the `Standing` table instantly. This keeps read page loads extremely fast.

🎮 Play & Aggregation Engine

Matches are played and recorded manually by the Tournament Admin:

  • Manual Results Entry: Tournament Admin fills out the detailed Enter Result form to submit exact scores and player statistics (goals, assists, cards, minutes) for a match.
  • Automatic Standings Update: Saving a result triggers the backend computation engine to instantly recalculate the standings table and re-rank top scorers.
